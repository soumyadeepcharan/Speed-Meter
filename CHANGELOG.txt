Features Implemented
--------------------
Network Speed (service/, data/, notification/)
- SpeedMonitorService: foreground service (START_STICKY). One monitoring
  coroutine (guarded by isMonitoring) samples TrafficStats every 1 second on
  Dispatchers.Default. It computes download and upload bytes per second from
  the deltas and the elapsed time. Counters that report UNSUPPORTED or fall are
  treated as zero.
- Icon speed type (added in 0.8.1): the status bar icon shows the total,
  download, or upload speed. Stored as iconSpeedType (Int 0, 1, or 2). The
  service collects this value and applies it on the next tick.
- Speed units (data/Speed.kt, formatSpeed):
  - BYTES_PER_SECOND (default): B/s, KB/s, MB/s, GB/s with base 1024.
  - BITS_PER_SECOND: b/s, Kb/s, Mb/s, Gb/s with base 1000, from bytes × 8.
  - Speed values use 0 decimals for the first two units and 1 decimal above that.
- Speed unit is stored as speedUnit (Int 0 or 1).

Daily Data Usage (service/SpeedMonitorService.kt, data/SettingsDataStore.kt)
- Totals are for the current local day, from midnight.
- With Usage access granted (AppOpsManager.checkOpNoThrow with
  OPSTR_GET_USAGE_STATS = MODE_ALLOWED):
  - Mobile total = NetworkStatsManager.querySummaryForDevice(type 0) from
    midnight to now, RX plus TX.
  - Wi-Fi total = the same query with type 1.
- Without Usage access (fallback):
  - A daily baseline (date, total bytes, Wi-Fi bytes) is stored in DataStore.
  - Totals are the current counters minus the baseline, floored at zero.
  - The baseline resets when the date changes.
  - Total device counters come from TrafficStats total minus Wi-Fi counters.
  - Wi-Fi counters come from TrafficStats.getRxBytes/getTxBytes on the first
    interface whose name starts with "wlan". If none exists, Wi-Fi is 0.
- Data usage unit is stored as dataUnit (Int 0, 1, or 2):
  - BITS_DECIMAL: b, Kb, Mb, Gb, Tb (base 1000, from bytes × 8).
  - BYTES_DECIMAL: B, kB, MB, GB, TB (base 1000).
  - BYTES_BINARY (default): B, KiB, MiB, GiB, TiB (base 1024).
- Data usage values use 0 decimals for the byte unit and 2 decimals above it.

Settings (data/SettingsDataStore.kt)
- DataStore Preferences named "settings".
- indicatorEnabled (Boolean, default false).
- themeMode (Int, default 0 = SYSTEM): SYSTEM(0), LIGHT(1), DARK(2).
- speedUnit (Int, default 0): BYTES_PER_SECOND(0), BITS_PER_SECOND(1).
- dataUnit (Int, default 2): BITS_DECIMAL(0), BYTES_DECIMAL(1), BYTES_BINARY(2).
- iconSpeedType (Int, default 0): TOTAL(0), DOWNLOAD(1), UPLOAD(2). New in 0.8.1.
- startOnBoot (Boolean, default false). New in 0.8.1.
- quitRequested (Boolean, default false). New in 0.8.1.
- dailyUsageDate (String), dailyDataBaseline (Long), dailyWifiBaseline (Long).
- Each enum has fromStorageValue(), which falls back to its default for unknown
  values.
- All flows fall back to empty preferences on IOException.

Quit (MainActivity.kt, ui/TopAppBar.kt) - new in 0.8.1
- The power icon in the top bar calls quitApp(), which:
  1. Sets indicatorEnabled to false and quitRequested to true (runBlocking).
  2. Sends SpeedMonitorService the ACTION_QUIT intent, which removes the
     foreground notification and stops the service.
  3. Cancels notification ID 1001.
  4. Calls finishAffinity() and Process.killProcess(myPid()).
- At the next launch, MainActivity sees quitRequested, clears it, and does not
  start the service. The indicator then stays off until the user turns it on.

Startup and Permission Flow (MainActivity.kt, ui/HomeScreen.kt, receiver/BootReceiver.kt)
- MainActivity creates the notification channel on every launch (new in 0.8.1).
- On launch:
  - If quitRequested is true, it is cleared and the service is not started.
  - If indicatorEnabled is false, nothing else happens.
  - Otherwise, on Android 13 and newer, the service starts if POST_NOTIFICATIONS
    is granted, or the permission prompt appears if it is not. On Android 8 to
    12, the service starts directly.
- Turning the Home switch on (HomeScreen.toggle): on Android 13 and newer without
  POST_NOTIFICATIONS, the prompt appears. If granted, the service starts and the
  setting is saved as on. If denied, the setting stays off. Otherwise the service
  starts and the setting is saved as on.
- Turning the switch off stops the service and saves the setting as off.

Boot Receiver (receiver/BootReceiver.kt) - new in 0.8.1
- Listens for android.intent.action.BOOT_COMPLETED only.
- Uses goAsync() and a Dispatchers.Default coroutine.
- Starts SpeedMonitorService as a foreground service only when all three are true:
  quitRequested is false, startOnBoot is true, and indicatorEnabled is true.
- The receiver does not request notification permission. If the app has not been
  granted it, the service still starts but the notification may not be shown.

Notification (notification/NotificationHelper.kt, res/layout/notification_layout.xml)
- Channel "netspeed_channel", named "Speed Meter" (IMPORTANCE_LOW, no badge).
- Ongoing, local-only, low-priority notification, Notification ID 1001.
- A new RemoteViews is created for each update. (0.8.0 reused one instance;
  0.8.1 reverted this.)
- Custom content view: a horizontal row of four text fields with equal weight
  (layout_weight 1), single line, ellipsised. Text: "Down: <value><unit>",
  "Up: <value><unit>", "Data: <value>", and "WiFi: <value>".
- The status bar icon shows the speed chosen in iconSpeedType.

Known Limitations and Issues
----------------------------
- Quit uses Process.killProcess after writing two settings on the main thread
  with runBlocking. This can cause a brief UI pause, and the app is terminated
  rather than closed cleanly. Move the writes to a background scope.
- The resource excludes for kotlin/** and *.kotlin_module may affect code that
  uses reflection. Test a signed release build before publishing.
- The battery optimization switch is on when optimization still applies. Some
  manufacturers add their own background restrictions beyond this setting.
- Start on boot does not request notification permission. If it has not been
  granted, the service starts without a visible notification.
- Without Usage access, daily totals are estimated from device counters since
  the day's first run. They can read lower after a phone restart.
- The Wi-Fi fallback needs an interface named "wlan*". On devices that use
  another name, Wi-Fi shows 0 until Usage access is granted.
- With Usage access, figures come from Android's usage records and can lag a
  few minutes behind real time.
- The status bar icon does not shrink long text. Very long values may be clipped.
- The notification's equal-weight fields may truncate long values on narrow
  screens.
- A duplicate import of graphicsLayer in HomeScreen.kt may produce a build
  warning. Remove the duplicate.
- No usage history, speed history, or speedometer gauge.
- Material 3 1.5.0-alpha03 is a pre-release and may show visual quirks.
- The Material 3 Adaptive libraries are still declared but not used.
- No unit or instrumented tests.
- No animated launcher icon (the animated drawable is not in this build).
