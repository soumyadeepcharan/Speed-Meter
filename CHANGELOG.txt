Speed Meter - Changelog & Technical Documentation
===================================================

[Version 2.0.0] - Current Release (versionName 2.0.0, versionCode 13)
-----------------------------------------------------------------------

OVERVIEW
--------
Speed Meter is a lightweight, real-time network speed monitor for Android,
built with Kotlin and Jetpack Compose (Material 3 Expressive). It runs as a
foreground service that keeps one status bar notification line up to date
with live download and upload speed and today's data usage.


TECHNOLOGY STACK
-----------------

Language & Platform:
  • Kotlin 2.1.20
  • Android minSdk 26 (Oreo), targetSdk and compileSdk 36
  • Java compatibility and JVM target: 17
  • Package: com.sdcgroup.speedmeter

UI:
  • Jetpack Compose with Material 3 (Compose BOM 2026.02.01,
    material3 1.5.0-alpha03)
  • Opt-in APIs: ExperimentalMaterial3Api, ExperimentalMaterial3ExpressiveApi
  • Material 3 Expressive animated-shape buttons (ButtonDefaults.shapes())
    through the shared appButtonShapes() helper: a rounded resting shape that
    morphs on press
  • Material Icons (core and extended)
  • Edge-to-edge rendering (enableEdgeToEdge) with transparent status and
    navigation bars; status and navigation bar icon contrast follows the theme
  • Device-matched corner shapes: the corner radius is read from
    View.Display.getRoundedCorner() on Android 12+ and used for all Material
    shape tokens; falls back to 28dp when unavailable
  • Custom components: gesture-driven Switch (thumb follows the finger),
    AppAlertDialog, bottom sheet helpers, and WindowSizeClass-based responsive
    layout
  • Dynamic Color (Material You) on Android 12+, with static light and dark
    fallback schemes
  • Bottom sheet drag handle (BottomSheetDefaults.DragHandle()), with sheet
    height that accounts for the status bar and square bottom corners
  • Orientation follows the system rotation lock (screenOrientation="user")

State & Data:
  • Jetpack DataStore Preferences for all settings and daily-usage baselines
  • Kotlin Coroutines and Flow for async work and reactive state
  • rememberSaveable for dialog and UI state across configuration changes
  • Last speed, icon, and usage strings cached in SpeedMonitorService so the
    notification can be rebuilt on configuration changes without waiting for
    the next tick

System Integration:
  • TrafficStats API: real-time speed from byte-counter deltas
  • NetworkStatsManager: per-day mobile and WiFi totals. Falls back to a
    TrafficStats-based daily baseline when Usage Access isn't granted.
  • Foreground service (dataSync type) with a RemoteViews notification
  • Configuration-change handling in the service re-posts the notification
    (onConfigurationChanged)
  • BroadcastReceiver for BOOT_COMPLETED (optional auto-start)
  • AppOpsManager.checkOpNoThrow for Usage Access checks
  • PowerManager for battery optimization status
  • Settings.ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS to request the
    exemption. Settings.ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS opens the
    system exemption list so the user can revoke it. Android has no API for
    an app to revoke its own exemption, so this is a deep link, not a one-tap
    action.
  • androidx.lifecycle.compose.LocalLifecycleOwner

Build System:
  • Android Gradle Plugin 8.11.0 via Kotlin DSL; Gradle wrapper 8.14.3
  • Version catalog: gradle/libs.versions.toml
  • R8/ProGuard minification and resource shrinking for release builds
  • Conditional release signing from release.properties (git-ignored)


FEATURES TO DATE
-----------------

✅ Real-Time Speed Monitoring
  • Download and upload speed from TrafficStats deltas, once per second
  • Total speed = download + upload
  • Handles TrafficStats.UNSUPPORTED and negative or decreasing counters
  • Display unit: bytes per second (B/s to GB/s) or bits per second
    (b/s to Gb/s), via the shared scaledMagnitude() helper with boundary-safe
    rounding (e.g. 999.99 KB/s doesn't roll into a wrong unit)
  • Below 1 MB/s or 1 Mb/s, values show as integers. Data and WiFi usage
    always show up to two decimal places.

✅ Persistent Status Bar Notification
  • One non-expandable line with four icon-led columns: download, upload,
    data, WiFi. Built from notification_layout.xml (RemoteViews) with
    equal-weight columns (LinearLayout weightSum = 4).
  • Each column: a 16sp icon in a rounded 4dp background (bg_notification_icon)
    with a vector drawable (ic_notification_down, _up, _data, _wifi), followed
    by a single-line TextView at 14sp with ellipsize="end"
  • Value text colors come from theme tokens: notification_value_color is
    #000000 in light mode and #FFFFFF in dark mode
  • Status bar icon: 192×192 ARGB bitmap (IconGenerator), with auto-shrink
    digit sizing and spacing measured from glyph bounds (getTextBounds())
  • Icon speed source is user-selectable: total, download only, or upload
    only (IconSpeedType)
  • Low-priority, local-only, "only alert once" notification
  • Notification channel is created once and reused across restarts

✅ Daily Data Usage Tracking
  • Midnight-to-now totals, not session-based accumulation
  • Primary path: NetworkStatsManager.querySummaryForDevice() for mobile
    (type 0) and WiFi (type 1), from start of day to now
  • Fallback (no Usage Access): TrafficStats daily baseline, stored in
    DataStore and reset at the start of each day
  • WiFi bytes come from the "wlan" interface; mobile = total − WiFi
  • Display unit: bits (decimal), bytes (decimal kB/MB/GB), or bytes
    (binary KiB/MiB/GiB), via the same scaledMagnitude() helper

✅ Indicator Enable/Disable
  • One home screen toggle starts and stops the foreground service
  • Custom Switch with live thumb tracking during drag (awaitEachGesture),
    not just tap-to-toggle. Track and thumb colors switch instantly with the
    checked state.
  • Off by default on first install
  • POST_NOTIFICATIONS requested only when enabling (API 33+)
  • Quit button in the top app bar: a compact 52×32dp filled button in the
    error color, centered in a reserved 108dp slot. It stops the service,
    cancels the notification, and ends the process.

✅ Settings Screen (single scrollable column, bottom padding respects the
   navigation bar)
  • Notification settings
    - Opens Android's per-app notification settings
    - Speed units (Bytes/sec or Bits/sec)
    - Data usage units (Bits decimal, Bytes decimal, Bytes binary)
    - Speed shown in the indicator icon (Total, Download, Upload)
  • Notification layout
    - Usage access: opens ACTION_USAGE_ACCESS_SETTINGS. Shown as a live
      Switch that reflects the real grant state, rechecked on every resume
      through a DisposableEffect lifecycle observer.
  • General
    - Theme (System, Light, Dark)
    - Start on boot toggle (persisted; read by BootReceiver)
    - Battery optimization toggle. Turning it on opens
      ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS. Turning it off opens
      ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS so the user can restore
      optimization. State is rechecked on every resume.
  • Support
    - Help & feedback bottom sheet: "Suggest a feature" and "Report a bug".
      Both open a pre-filled email. Bug reports include app version, device
      model, device name, and Android version.
    - About dialog with app version
  • Option rows and dialogs use MaterialTheme.shapes.extraLarge, so ripples
    and corners follow the rounded design

✅ Theming
  • Material 3 light and dark schemes with Material You dynamic color on
    Android 12+
  • Shape tokens (extraSmall through extraLarge) all use the device-matched
    corner radius
  • Theme state comes from one collector; key(themeMode) on the top app bar
    avoids visible lag when switching themes
  • Status and navigation bar icon appearance follows the active theme;
    navigation bar contrast enforcement is disabled on Android 10+

✅ Responsive Layout
  • WindowWidthSizeClass and WindowHeightSizeClass (ExtraCompact through
    ExtraLarge), with per-class defaults in WindowSizeDefaults
  • Settings dialogs scroll internally (ScrollableDialogContent, capped at
    50% of screen height), so they fit any window size
  • rememberSaveable keeps dialog state across rotation

✅ Permissions & Background Reliability
  • Runtime POST_NOTIFICATIONS request (API 33+); no-op on older versions
  • Usage Access flow with live status refresh on resume
  • Battery optimization flow with live status refresh on resume, plus a
    path to reopen the exemption list to reverse it
  • BootReceiver: if "Start on boot" is on, clears the quit flag, turns the
    indicator on, and starts the foreground service after a device boot,
    even if the user quit or turned the indicator off before shutdown
  • START_STICKY restart policy. SupervisorJob-scoped coroutines are
    cancelled in onDestroy.


ARCHITECTURE
-------------

Single-Activity, Service-Backed:
  • MainActivity: single entry point. Hosts the Compose UI, enables
    edge-to-edge, and handles initial permission and service bootstrap.
  • SpeedMonitorService: foreground service that owns the monitoring loop,
    independent of the UI lifecycle
  • NotificationHelper: channel creation and RemoteViews notification
  • IconGenerator: 192×192 bitmap status bar icon

Data Flow:
  TrafficStats (deltas) → speed calculation → formatSpeed() → notification
  NetworkStatsManager or TrafficStats baseline → getTodayUsage() →
  formatDataUsage() → notification
  Last notification state cached in the service → rebuilt on
  onConfigurationChanged
  DataStore Flows → service and UI state (speed unit, data unit, icon type,
  indicator enabled, start on boot, quit requested, daily baseline)

State Management:
  • DataStore Preferences is the single source of truth for settings
  • Flow.collect in the service applies setting changes without restarting
    monitoring
  • Compose collectAsState and rememberSaveable for UI state

KNOWN LIMITATIONS
-------------------
• Speed reflects system-wide TrafficStats, not per-app traffic
• Notification values use a fixed 14sp size with ellipsis. Very long values
  are cut off with "…" (the adaptive-size behavior from 1.0.0 was replaced).
• Without Usage Access, daily usage is an estimate from a stored baseline,
  not full system accounting
• Only "today" totals. No history or graphs.
• The live speed doesn't show network type (WiFi or mobile)
• No speed thresholds or alerts
• Turning battery optimization back on needs the user to find the app in
  the system exemption list and toggle it. Android has no API for an app to
  revoke its own exemption in one tap.
• Pre-release Material 3 (1.5.0-alpha03): minor visual quirks may appear

BUILD & RELEASE
-----------------
Debug build:
  ./gradlew assembleDebug

Release build:
  Create release.properties in the project root:
    storeFile=<path/to/keystore>
    storePassword=<password>
    keyAlias=<alias>
    keyPassword=<password>
  ./gradlew assembleRelease

Release signing is applied only if release.properties exists and has all
four keys. Otherwise the release build is unsigned.
