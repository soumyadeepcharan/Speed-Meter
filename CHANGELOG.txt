Features Implemented
--------------------
Network Speed (service/, data/, notification/)
- SpeedMonitorService: foreground service (START_STICKY). One monitoring
  coroutine (guarded by isMonitoring) samples TrafficStats every 1 second on
  Dispatchers.Default. It computes download and upload bytes per second from
  the deltas and the elapsed time. Counters that report UNSUPPORTED or fall are
  treated as zero.
- Speed units (data/Speed.kt, formatSpeed):
  - BYTES_PER_SECOND (default): B/s, KB/s, MB/s, GB/s with base 1024.
  - BITS_PER_SECOND: b/s, Kb/s, Mb/s, Gb/s with base 1000, from bytes × 8.
  - Speed values use 0 decimals for the first two units and 1 decimal above that.
- Speed unit is stored as speedUnit (Int 0 or 1).

Daily Data Usage (service/SpeedMonitorService.kt, data/SettingsDataStore.kt)
- Totals are for the current local day, from midnight.
- With Usage access granted (AppOpsManager.checkOpNoThrow with
  OPSTR_GET_USAGE_STATS = MODE_ALLOWED):
  - Mobile total = NetworkStatsManager.querySummaryForDevice(type 0) from
    midnight to now, RX plus TX.
  - Wi-Fi total = the same query with type 1.
- Without Usage access (fallback):
  - A daily baseline (date, total bytes, Wi-Fi bytes) is stored in DataStore.
  - Totals are the current counters minus the baseline, floored at zero.
  - The baseline resets when the date changes.
  - Total device counters come from TrafficStats total minus Wi-Fi counters.
  - Wi-Fi counters come from TrafficStats.getRxBytes/getTxBytes on the first
    interface whose name starts with "wlan". If none exists, Wi-Fi is 0.
- Data usage unit is stored as dataUnit (Int 0, 1, or 2):
  - BITS_DECIMAL: b, Kb, Mb, Gb, Tb (base 1000, from bytes × 8).
  - BYTES_DECIMAL: B, kB, MB, GB, TB (base 1000).
  - BYTES_BINARY (default): B, KiB, MiB, GiB, TiB (base 1024).
- Data usage values use 0 decimals for the byte unit and 2 decimals above it.

Settings (data/SettingsDataStore.kt)
- DataStore Preferences named "settings".
- indicatorEnabled (Boolean, default false).
- themeMode (Int, default 0 = SYSTEM): SYSTEM(0), LIGHT(1), DARK(2).
- speedUnit (Int, default 0): BYTES_PER_SECOND(0), BITS_PER_SECOND(1).
- dataUnit (Int, default 2): BITS_DECIMAL(0), BYTES_DECIMAL(1), BYTES_BINARY(2).
- dailyUsageDate (String), dailyDataBaseline (Long), dailyWifiBaseline (Long).
- Each enum has fromStorageValue(), which falls back to its default for unknown
  values.
- All flows fall back to empty preferences on IOException.

Startup and Permission Flow (MainActivity.kt, ui/HomeScreen.kt)
- On launch, MainActivity reads indicatorEnabled once. If it is off, nothing else
  happens. No permission prompt is shown, and no service is started.
- If it is on:
  - On Android 13 and newer, if POST_NOTIFICATIONS is granted, the service starts.
    If not, the permission prompt appears. The service starts only if the user
    grants it.
  - On Android 8 to 12, the service starts directly.
- Turning the Home switch on (HomeScreen.toggle):
  - On Android 13 and newer without POST_NOTIFICATIONS, the permission prompt
    appears. If granted, the service starts and the setting is saved as on. If
    denied, the setting stays off.
  - Otherwise, the service starts and the setting is saved as on.
- Turning the switch off stops the service and saves the setting as off.
- SpeedMeterApp collects themeMode, speedUnit, and dataUnit, and passes setter
  callbacks down. Each setter saves the value and then closes its dialog.

Notification (notification/NotificationHelper.kt, res/layout/notification_layout.xml)
- Channel "netspeed_channel", named "Speed Meter" (IMPORTANCE_LOW, no badge).
- Ongoing, local-only, low-priority notification, Notification ID 1001.
- One RemoteViews instance is created in the helper and updated on each tick.
- Custom content view: a horizontal row of four text fields, each with a fixed
  width (Down 70dp, Up 60dp, Data 85dp, WiFi 82dp), single line, ellipsised.
  Text: "Down: <value><unit>", "Up: <value><unit>", "Data: <value>", and
  "WiFi: <value>".
- The status bar icon shows the total speed only.

Status Bar Icon (notification/IconGenerator.kt)
- 96 x 96 transparent bitmap, drawn with fixed positions.
- Speed value: sans-serif-condensed bold, 65sp, textScaleX 0.98, letterSpacing
  -0.08, drawn centred at x = 48, baseline y = 52.
- Unit text: sans-serif-condensed bold, 40sp, textScaleX 1, letterSpacing
  -0.05, drawn centred at x = 48, baseline y = 95.
- The text is not auto-sized. Very long values may be clipped.

Home Section (ui/HomeScreen.kt, HomeScreen)
- A card (surfaceContainer, extraLarge shape) with a NetworkCheck icon, the
  title "Enable indicator", the subtitle "Show network speed in the status bar",
  and the custom Switch.
- The whole row toggles the setting (Role.Switch).
- The row is not drawn until the saved value has loaded.

More Section (ui/HomeScreen.kt, MoreScreen)
- Sections, in order:
  1. Notification settings
     - Notification settings: opens Settings.ACTION_APP_NOTIFICATION_SETTINGS.
     - Speed units: opens SpeedUnitDialog, with the current value as the subtitle.
     - Data usage units: opens DataUnitDialog, with the current value as the subtitle.
  2. Notification layout
     - Usage access: a switch row. The switch shows the current grant state.
       Tapping the row, or the switch, opens ACTION_USAGE_ACCESS_SETTINGS.
     - The grant state is checked when the screen first appears and again each
       time the screen resumes (DisposableEffect with ON_RESUME).
  3. General
     - Choose theme: opens ThemeDialog. The subtitle is System default, Light
       mode, or Dark mode.
     - Help & feedback: opens HelpFeedbackBottomSheet.
     - About: opens AboutDialog.
  4. Footer: "Made with ❤️ from India by SDC Group".
- Help & feedback sheet (HelpFeedbackBottomSheet):
  - A ModalBottomSheet with no drag handle, skipPartiallyExpanded = true, and a
    body height of 30% of the screen.
  - Two rows: "Suggest a feature" and "Report a bug". Each opens an ACTION_SENDTO
    intent to sdcgroupofficial@gmail.com with a prefilled subject and body from
    strings.xml. The bug report template includes the app version, device model
    (Build.MODEL), device name (Build.DEVICE), and Android version and API level.
  - Choosing a row closes the sheet. Content fades and slides in on open.
- Dialogs are AppAlertDialog instances with radio-style options in a
  selectableGroup. Option rows are clipped to MaterialTheme.shapes.extraLarge.
- Dialog state uses rememberSaveable, so dialogs survive rotation.
- The page is one verticalScroll Column in SpeedMeterHomeMoreContent.

Custom Switch (ui/UiWidgets.kt)
- Track 52 x 32 dp, thumb 24 dp with 4 dp padding.
- Tap toggles. A horizontal drag moves the thumb. Release snaps to on or off,
  using the midpoint, or toggles on a tap.
- The thumb shows a Close icon when off and a Check icon when on. The icons
  cross-fade as the thumb moves past the midpoint.
- Thumb movement and track and thumb colours use spring animations with
  StiffnessHigh.
- Haptic feedback on release.
- Role.Switch and a configurable contentDescription.

Dialogs (ui/UiWidgets.kt)
- AppAlertDialog uses DialogProperties(decorFitsSystemWindows = true), so
  dialogs stay inside system bars.
- AppAlertDialog content is wrapped in ScrollableDialogContent, which limits
  height to 50% of the screen and scrolls.

Top Bar (ui/TopAppBar.kt)

- Pinned scroll behaviour.

Known Limitations
-----------------
- Without Usage access, daily totals are estimated from device counters since
  the day's first run. They can read lower after a phone restart, because the
  counters restart too.
- The Wi-Fi fallback needs an interface named "wlan*". On devices that use
  another name, Wi-Fi shows 0 until Usage access is granted.
- With Usage access, figures come from Android's usage records and can lag a
  few minutes behind real time.
- The status bar icon uses fixed positions and does not shrink long text. Very
  long values may be clipped.
- The notification's fixed field widths may truncate long values.
- No usage history, speed history, or speedometer gauge.
- Material 3 1.5.0-alpha03 is a pre-release and may show visual quirks.
- The Material 3 Adaptive libraries are still declared but not used.
- No unit or instrumented tests.
- No animated launcher icon (the animated drawable is not in this build).
